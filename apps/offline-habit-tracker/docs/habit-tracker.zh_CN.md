# 离线习惯打卡

习惯打卡是一个独立的 240 × 320 应用。它用 GitHub 风格的 13 周每日热力图
彻底替换硬件测试菜单，并让打卡记录和用户照片在掉电后仍然保留。

## 按键操作

| 页面 | UP | DOWN | OK |
| --- | --- | --- | --- |
| 热力图 | 前一天 | 后一天 | 切换选中日期的打卡状态 |
| 热力图，长按 | 打开照片上传 | 前 13 周 | 设置离线日期 |
| 日期设置 | 增加当前字段 | 减少当前字段 | 下一字段；在日期字段保存 |
| 照片上传 | 长按停止本地热点并返回 | 无操作 | 无操作 |
| 照片屏保 | 任意键唤醒热力图，但不执行该键原本的操作 | | |

至少保存一张照片后，热力图连续三秒没有输入就会进入照片屏保，照片每五秒
轮换一次。本地 Wi-Fi 热点只在照片上传页面开启。

## 通过手机上传照片

设备会临时建立一个 WPA2 Wi-Fi 热点，并直接提供上传网页。Android 和 iPhone
的普通浏览器都可使用，无需 Web Bluetooth、专用 App 或互联网连接。

1. 在设备热力图页面长按 **UP**，进入 `ADD PHOTOS` 页面。
2. 扫描 Passport 屏幕上的 Wi-Fi 二维码。若手机无法识别，请用屏幕显示的
   `FoloHabit-XXXX` 名称和固定密码 `12345678` 手动连接。热点仅在照片上传
   页面开启。
3. 在手机浏览器打开 `http://192.168.4.1`。部分手机连接热点后会自动打开
   本地上传页。
4. 选择照片并上传；在网页确认完成前保持连接 Passport 热点，可继续重复
   上传更多照片。
   照片管理区会显示所有已保存照片的缩略图。单张删除和删除全部都需要在
   4 秒内再次点按页面内按钮确认，不依赖手机热点弹窗可能屏蔽的浏览器确认框；
   即使 13 个槽位已满，仍然可以进入该页面管理照片。
5. 在设备上长按 **UP**，停止热点并返回热力图。

网页会把每张照片居中裁剪成 240 × 320，并在传输前转换成 RGB565。固件最多
接收 13 张照片。每次上传会写入已擦除的槽位，再从 Flash 读回并校验 CRC，
最后才提交到带双副本的清单；中断或损坏的上传不会加入轮播。
删除时会先提交双副本清单，再回收图片槽位，因此删除过程中断电不会让已从
清单移除的照片重新出现在轮播中。

## 持久化布局与烧录

本应用使用如下 8 MB Flash 布局：

| 分区 | 偏移 | 大小 | 内容 |
| --- | ---: | ---: | --- |
| `nvs` | `0x9000` | 24 KiB | 打卡记录与 ESP-IDF 数据 |
| `phy_init` | `0xF000` | 4 KiB | PHY 初始化数据 |
| `factory` | `0x10000` | 6080 KiB | 应用固件 |
| `photos` | `0x600000` | 2048 KiB | 最多 13 张 RGB565 照片和双副本元数据 |

开发更新若需要保留现有打卡记录和照片，只烧录 `0x0` 的 bootloader、
`0x8000` 的分区表和 `0x10000` 的应用。此时不要全片擦除，也不要从 `0x0`
写入合并镜像，因为其中的填充内容可能重置数据分区。新分区表必须继续兼容
上述偏移。

只在空白设备初始化或有意完整刷新时使用验证后的合并镜像。仓库通用烧录策略
见[固件布局](development/engineering/firmware-layout.zh_CN.md)。
